# M2.11 Correction Brief - Immutable Review Approval

Date: 2026-08-27
Status: Complete

## Observed Failure

The Review Human Gate records a room-level `approved` decision, but it does not publish a distinct immutable record of the exact Artifact version, Change Set, verification scope, and human edits visible at approval time.

## User Artifact

An immutable approved Review Artifact snapshot that identifies whether Artifact v2 or v3 was approved, contains the exact approved text and Change Set, retains the model-v2 verification result and any Chair-edited Change IDs, and restores from Meeting History without credentials.

## Baseline

v0.11i persists Artifact v2, optional Human Revision Artifact v3, and a room decision separately. The relationship is inferable but not frozen as one approval artifact.

## Smallest Hypothesis

Creating one deterministic snapshot inside the existing approve transaction will make approval auditable and recoverable without a provider call or new protocol phase.

## Expected Information Gain

No model call is added. The slice tests whether the existing Review result and Human Revision contracts contain enough information to publish an exact approved version.

## Acceptance Checks

- Only an `approved` Review decision creates the snapshot; rejection does not.
- The snapshot binds the source State version and exact Review result creation identity.
- Artifact v3 approval also binds the exact Human Revision timestamp and edited Change IDs.
- Approved text and Change Set are deterministically identical to the visible v2 or v3 result.
- Verification scope states that model checks cover v2; approval never rewrites the verifier verdict.
- Saving the decision and snapshot is atomic from the UI perspective; a storage failure rolls both back.
- The snapshot persists as a separate credential-free Artifact and restores with old records remaining readable.
- Build, ESLint, automated tests, and `git diff --check` pass.

## Cost Boundary

Zero provider calls and zero paid tokens. Browser QA may use only existing local state.

## Stop Condition

Stop if immutable approval requires a new provider phase, generic signing infrastructure, account identity, cloud synchronization, or database migration. Cryptographic signatures and cross-device authority remain later concerns.

## Result

The hypothesis passed locally. Approving a Review now creates a source-bound immutable snapshot of the visible Artifact v2 or v3, exact Change Set, original model verification, human-edited Change IDs, and approval time. The snapshot and room decision share the existing durable save boundary; storage failure rolls back the snapshot, decision, and protocol completion together. Rejection creates no snapshot.

Production build, ESLint, `git diff --check`, and all twenty-nine automated tests pass. Tests reject a v2 snapshot when a Human Revision is currently visible and reject altered verification verdicts. Browser checks at 1280x800 and 390x844 found no page overflow or console warning. The local browser still had no saved Review result, so no provider call was made solely to stage the approved-result UI.

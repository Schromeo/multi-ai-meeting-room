# M2.11 Correction Brief - Item-Level Change Editing

Date: 2026-08-27
Status: Complete

## Observed Failure

Artifact v2 Benchmark 005 reached the Human Gate with a deterministic Change Set, but the Chair could only approve or reject the whole result. A semantically weak individual rewrite could not be corrected without spending another broad model round.

## User Artifact

A Chair-editable Review result in which each proposed Change keeps its immutable source text, Finding lineage, location, rationale, and model verification, while the Chair may edit its replacement text and receive an application-derived Artifact v3. The interface must state that model verification covers v2, not the human edit.

## Baseline

The current v0.11h result renders read-only Artifact v2, Change Set, Verification, and Brief tabs. Human control is whole-artifact approve, reject, or another-round direction.

## Smallest Hypothesis

Adding bounded item-level replacement editing at the existing Human Gate will improve adoptability without another provider call or broader protocol change.

## Expected Information Gain

No model call is added. The slice tests whether the existing source-linked Change Set is sufficient to support human correction and durable restoration.

## Acceptance Checks

- Only a Change's `after` text is editable; source and lineage fields remain immutable.
- Unknown Change IDs, unchanged drafts, oversized replacements, source mismatches, ambiguity, and overlaps are rejected deterministically.
- Artifact v3 is always derived by application code from immutable Artifact v1 and the edited Change Set.
- Human edits are visibly distinguished from model-verified v2 content.
- The revision persists in Meeting History and restores without credentials.
- Existing v2 records remain readable.
- Automated tests, production build, ESLint, and `git diff --check` pass.

## Cost Boundary

Zero provider calls and zero paid tokens. Only local deterministic tests and browser QA are allowed.

## Stop Condition

Stop and split the slice if item editing requires changing provider prompts, replaying Review, introducing a new generic workflow engine, or weakening source-lineage validation. Immutable final approval remains a following M2.11 slice unless it can reuse this revision record without expanding scope.

## Result

The hypothesis passed locally. The Chair can edit one replacement, restore model text, and receive an application-derived Artifact v3 while the original Change identity and Finding lineage remain immutable. Artifact v3 and its revision record persist separately; the UI states that model verification covers v2. No provider prompt, model call, or generic protocol phase changed.

Production build, ESLint, `git diff --check`, and all twenty-nine automated tests pass. Browser QA at 1280x800 and 390x844 found no page overflow or console warning. The refreshed local browser had no saved Review result, so interactive v3 Decision-page QA remains for the next naturally produced or restored fixture; no paid room was created solely for visual proof.

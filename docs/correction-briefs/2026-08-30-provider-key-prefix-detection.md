# Provider Key Prefix Detection Correction Brief

- **Observed failure:** a current Gemini authorization key beginning with `AQ.` remains ambiguous because Setup only recognizes the older `AIza` standard-key prefix. The user must manually choose Google Gemini even though the format is known.
- **User artifact:** a connection Setup flow that offers a high-confidence local provider hint for supported current key prefixes while preserving explicit manual choice for every unknown format.
- **Smallest hypothesis:** ordered, pure, locally tested prefix rules for the three supported providers are enough. Anthropic must be checked before OpenAI because both use an `sk-` family; Gemini needs both `AIza` and `AQ.`; unknown formats remain unresolved.
- **Change boundary:** move prefix inference out of the page into one pure module, add Gemini `AQ.` recognition, preserve the existing Anthropic and OpenAI forms, and add offline regression coverage. Do not add unsupported providers or infer provider identity from model names.
- **Acceptance:** `AQ.` and `AIza` map to Gemini; `sk-ant-` maps to Anthropic before generic `sk-`; supported OpenAI forms map to OpenAI; whitespace is ignored; unknown and wrong-case formats remain `null`; Setup still requires manual provider selection before any verification request when inference is ambiguous.
- **Security, cost and stop boundary:** detection reads only the local prefix and never sends a key anywhere. Verification continues to call only the explicitly selected or locally inferred provider, with no cross-provider probing, retries, live model calls or credential persistence. Stop after offline build, tests, lint, type check and bilingual documentation.
- **Current source basis:** Google documents the transition from standard to authorization keys in [Using Gemini API keys](https://ai.google.dev/gemini-api/docs/api-key); a [Google AI Developers Forum response](https://discuss.ai.google.dev/t/api-key-to-start-with-aiza/169453) identifies the new authorization-key family as `AQ`, with current examples using `AQ.`. Prefixes remain non-contractual implementation hints and must be revised when providers change them.

# DP-0.2 Engineering Portability Correction Brief

- **Observed failure:** the DP-0.1 Windows baseline has four independently reproducible failures. `dev`/`build`/`start` use POSIX-only inline environment assignment, so standard build and test stop before vinext. One source-inspection test assumes bare LF although Git produces a CRLF Windows working tree. TypeScript lacks Cloudflare runtime/module declarations for `cloudflare:workers`, `Fetcher`, and `D1Database`. There is no single command or repository-local CI matrix that classifies install, build, tests, lint, and types consistently.
- **User artifact:** one cross-platform repository validation path that a developer or CI runner can execute without translating commands or interpreting inherited failures, while keeping inactive D1 infrastructure visibly optional.
- **Baseline:** on Windows NT 10.0.26200.0 with Node 24.19.0 and pnpm 11.19.0, frozen install and lint pass; `pnpm build` and `pnpm test` stop on `WRANGLER_LOG_PATH=...`; direct tests pass 62/63 with `updateSeatHandler` extraction failing on CRLF; `pnpm exec tsc --noEmit --incremental false` reports exactly the three Cloudflare declaration errors recorded in the [DP-0.1 baseline](../evaluations/2026-09-19-dp-0-1-repository-baseline.md).
- **Smallest hypothesis:** a repository-owned vinext launcher can set the log-path environment value portably without another dependency; newline normalization can make the source assertion platform-independent without weakening its semantic check; Wrangler-generated runtime types plus a narrow optional D1 binding augmentation can describe the actual configuration; and one ordered `pnpm check` script can be shared by local development and a two-OS GitHub Actions matrix.
- **Expected information gain:** the complete local check will show whether these four defects fully explain the dirty Windows matrix. A repository-local workflow will show the intended CI contract; actual remote runner evidence remains pending until the workflow is committed and run.
- **Change boundary:** add one small vinext launcher, regenerate ignored Cloudflare runtime declarations from the pinned Wrangler/config compatibility date at the start of the canonical check, add only the optional `DB` typing that the inactive scaffold actually expects, normalize newlines inside the affected source test, separate `test` from `build`, add `typecheck`, `check`, and worker-type generation scripts, and add a Node 22.13 / pnpm 11.19 Windows-plus-Ubuntu workflow. Do not change application behavior, dependencies, provider code, D1 configuration, UI, Review/Plan artifacts, or deployment.
- **Acceptance checks:** frozen install remains unchanged; `pnpm build`, `pnpm test`, `pnpm lint`, `pnpm typecheck`, and `pnpm check` all pass on the Windows checkout; tests remain 63/63 rather than being removed or loosened; worker types are regenerated before TypeScript consumes them; CI YAML parses and invokes exactly the same `pnpm check`; no npm command or second lockfile returns; `git diff --check` passes.
- **Cost and security boundary:** zero provider calls, zero API spend, no new package, no dependency upgrade, no browser-record mutation, no deployment, no public credential, and no external repository/account write. Generated types come from the already pinned local Wrangler package and checked configuration.
- **Stop condition:** stop after the local matrix and workflow contract are clean. Do not advance DP-0.2 to Complete unless actual CI evidence exists or the milestone explicitly records CI as pending; do not use this portability slice to begin DP-0.3 interface work.

# DP-0.3 — Ordinary Meeting provider timeout after speech-depth change

- **Observed failure:** the owner supplied a P2 source receipt for a `gpt-5-pro` Proposal attempt with `callStatus=timeout`, unknown provider finish/usage and 90,002 ms elapsed. The ordinary `streamProvider` path has a fixed 90,000 ms application timer, even though Lite/Medium/Uncapped now request different statement depths and provider output caps.
- **User artifact:** a bounded Meeting call that gives a slow provider a reasonable opportunity to complete and either publishes its validated statement or records an honest timeout, without hidden retries or invented usage.
- **Baseline:** `PROVIDER_TIMEOUT_MS=90_000` aborts all non-Plan provider requests. The ordinary room budget is based on 90,000 ms per turn, so changing only the request timer would risk a successful slow call exhausting the next phase's cumulative time gate. The screenshot does not establish whether the provider would have completed or how many tokens it used.
- **Smallest hypothesis:** give ordinary participant/synthesis calls finite profile-sensitive application deadlines (Lite 180 s, Medium 240 s, Uncapped 300 s) and align their room-level time budget with the same maximum per turn. Keep other provider call families at their existing 90 s timer, and keep Plan's no-application-deadline policy. Preserve explicit Stop, no automatic retry, strict Turn Envelope validation and unknown receipt fields.
- **Expected information gain:** fake-timer tests can identify the exact abort boundary for each profile and prove parent cancellation, Plan exemption and non-ordinary default behavior without a paid call. Budget fixtures can prove the next phase is not blocked merely because a permitted call took longer than 90 s.
- **Acceptance:** no ordinary profile aborts at 90 s; each still aborts at its declared finite deadline; cancellation remains immediate; source receipt classification stays `timeout` with unknown finish/usage when unreported; room cumulative time does not contradict the new per-call allowance; `pnpm.cmd check` passes.
- **Cost boundary:** zero live provider calls, no retry, new dependency, schema migration or deployment. A longer wait can increase actual provider spend and delay; existing output-token, turn-count and explicit human-stop bounds remain. No claim of model quality or provider completion.
- **Stop:** if the host/provider itself terminates earlier, do not add an unbounded runner or infer billing from the receipt. Record that limitation and require a separately authorized live check before claiming the screenshot's model now completes.

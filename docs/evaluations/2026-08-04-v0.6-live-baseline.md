# v0.6 Live Baseline 001

**Date:** 2026-08-04

**Status:** Completed through the Human Gate; no human decision or revision was submitted.

**Objective:** Decide the narrowest useful version of a multi-AI meeting room.

## Test Scope

- Session-only BYOK connections for OpenAI and Anthropic.
- Successful room: OpenAI `gpt-5-mini` as Strategist and Anthropic `claude-haiku-4-5-20251001` as Critical Reviewer.
- One protocol iteration only: two independent proposals, two assigned cross-reviews, and one synthesis.
- The OpenAI Strategist also performed synthesis because v0.6 does not yet expose a separate Final Synthesizer.
- No revision was requested and the Human Gate remains pending for the user.

## Compatibility Probe

The first attempt used OpenAI `gpt-4.1-mini`. OpenAI rejected the proposal request with:

```text
Unsupported parameter: 'reasoning.effort' is not supported with this model.
```

Anthropic completed its proposal, after which the room stopped because fewer than two proposals succeeded. It did not automatically retry, cross-review, or synthesize. This is correct bounded-failure behavior, but the selectable OpenAI model list currently overstates runtime compatibility because the adapter sends model-specific optional controls to every OpenAI model.

## Independent OpenAI Baseline

The first OpenAI proposal was produced before either model saw the other's work, so it is preserved as the in-room single-model baseline for this evaluation. It recommended:

- a general synchronous room with three to five AI participants and one human chair;
- role assignment, turn taking, a shared agenda/state store, moderation controls, and a searchable transcript;
- no external networking, autonomous background work, file execution, or persistent agent memory by default;
- a human decision on networking level, maximum agent count, and persistence.

This is not a separately timed standalone API call, so it is adequate for content-delta comparison but not for a full single-model cost or latency comparison.

## Multi-Model Delta

The Anthropic proposal and the two directed reviews added several consequential items absent from the independent OpenAI proposal:

- narrow the initial product to a recurrent decision class rather than a general meeting room;
- prefer role asymmetry tied to different error costs, such as precision, recall, and assumption auditing;
- make chair competence and cognitive load explicit system constraints;
- require a three-to-five-instance pilot with measurable pass criteria;
- distinguish empirical claims from assumptions and value judgments;
- preserve disputes about agent count, networking, scope breadth, and chair capability.

The final memo incorporated these additions and retained unresolved disputes instead of presenting false consensus. This is a real positive signal for structured cross-model review.

## Risks Exposed

- **Reading burden:** 3,424 output tokens for a 62-character objective is too verbose for routine use. The protocol needs Turn Envelopes, card limits, Round Briefs, and targeted context.
- **Epistemic leakage:** generated thresholds such as four-hour meetings, 30-second overrides, three years of chair experience, or five prior decisions are design hypotheses, not evidence. Some were promoted into the memo despite being arbitrary.
- **System-role bias:** synthesis silently reused the OpenAI Strategist instead of an explicitly selected, separately accountable Final Synthesizer.
- **Compatibility:** model discovery proves key access and model visibility, not that every optional generation parameter is supported.
- **Human control:** v0.6 gives the user a final gate but no safe in-meeting checkpoint or scoped directive.

## Gate Result

**Pass to the next architecture milestone, with a compatibility fix first.**

The live path proves that two real providers can complete proposal, assigned review, synthesis, usage reporting, persistence, and a bounded Human Gate. It does not yet prove broad product-market value. The observed verbosity, arbitrary-detail promotion, system-role ambiguity, and final-only human control directly support the approved Protocol v1 design.

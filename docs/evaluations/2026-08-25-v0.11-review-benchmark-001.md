# v0.11 Review Benchmark 001

**Date:** 2026-08-25

**Status:** Two bounded runs completed and rejected at the Human Gate. No third paid run was made.

**Objective:** Improve a software-engineering resume for truthful Google Early Career recruiter screening, prioritizing material fit, evidence quality, scanability, and claims requiring user verification.

## Test Scope

- Artifact v1: the supplied resume body with name, phone, email, LinkedIn, and GitHub identifiers removed before provider transmission.
- References: the archived Google job-description summary from the prior user discussion. The original job URL was unavailable during this evaluation, so the reference explicitly prohibited inference about current posting status or eligibility.
- Truth constraints: no invented metrics, dates, responsibilities, qualifications, citations, accessibility work, or AI-tool impact; bracketed placeholders remain unresolved.
- OpenAI `gpt-4.1-mini` as Strategist and Anthropic `claude-haiku-4-5-20251001` as Critical Reviewer.
- Checkpoints mode, one round, Observer off, two independent Finding turns, two cross-reviews, and one synthesis per run.
- User-approved operating ceiling carried forward from the bounded smoke: `$0.10` advisory application estimate.

## Useful Findings

Both runs identified several actionable evidence problems:

- delete unresolved `[FILL IN]`, `[X]`, and measurement placeholders rather than submitting them;
- keep HBase cache tuning qualitative unless a measured before/after result exists;
- add baseline or validation context for the approximately 50% Nature Conservancy improvement, or weaken the claim if it cannot be verified;
- explain AI-tool usage truthfully rather than inventing an impact KPI merely to mirror the job description;
- preserve the resume's strong distributed-systems, information-retrieval, full-stack, and open-source evidence.

These overlap with the prior manual GPT-to-Claude review but were recovered from one bounded shared-source workflow.

## Run A Failure

The application did not provide trusted current-date context. Both providers incorrectly treated 2024 or 2025 entries as future dates. A Human Chair correction supplied `2026-08-25`, followed by a veto against the false timeline Findings, but later model turns still promoted the same Claim. The final Review Brief contradicted itself by rejecting part of the timeline concern while recommending correction of the same past-dated employment entry.

The memo was rejected. This exposed that free-text Chair Directives were advisory prompts rather than binding item decisions.

## Run B Evidence After the First Fix

The server supplied the trusted current date, eliminating the original future-date error. Anthropic then produced a different weak inference: a 2019 summer internship preceding a 2022 graduation was treated as a credibility problem. At the Proposal checkpoint, the Chair accepted Findings 1, 2, and 5 and rejected Finding 6 using new item-level controls.

The cross-review repeated the rejected timeline concern, but Canonical State correctly retained `rejected_by_chair`; later support and objections could not override the Human Choice. Review synthesis read Canonical State without raw reviewer statements and correctly stated that the internship timeline was accepted as written.

The resulting output still failed the product artifact contract: it omitted all five required Review Brief headings and added an unsupported suggestion about GitHub links. The memo was rejected. Application code now validates all required headings exactly once and in order, emits a visible format failure, and never retries automatically.

## Gate Result

**Partial pass; continue M2.11 without another paid retry.**

The Review Agenda, shared source bundle, independent Findings, checkpoint decisions, local audit trail, and binding Human Chair authority now have real evidence. The detailed Review Brief contract did not pass live, and Artifact v2 does not exist yet. The final code correction has deterministic coverage but was not paid-retested because the combined estimate reached `$0.087` of the `$0.10` ceiling.

## Product Decisions From Evidence

1. Inject trusted temporal context for Review rather than expecting models to infer the current date.
2. Free-text correction and veto remain useful context, but Claim acceptance or rejection must be a typed deterministic Human Choice.
3. Once decided by the Chair, later model updates may add audit evidence but cannot alter Claim status.
4. Review synthesis reads Canonical State only; rejected Claims are binding exclusions and resolved Disputes are not open.
5. Required Artifact structure is validated by application code, not prompt prose.

## Next Action

The next resume benchmark should compare the detailed revised artifact against this saved baseline and keep total user-visible reading effort as an evaluation metric.

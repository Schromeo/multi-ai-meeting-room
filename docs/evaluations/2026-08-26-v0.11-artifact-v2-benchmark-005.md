# Artifact v2 Benchmark 005

Date: 2026-08-26

## Question

Can the bounded Review Task Pack turn a realistic software-engineering resume and an archived Google Early Career job-description summary into a detailed, source-linked Artifact v2 that is more truthful and useful than Artifact v1?

## Bounds

- Human-approved operating ceiling: `$0.10` application estimate.
- Seats: OpenAI `gpt-4.1-mini` as Strategist/Editor and Anthropic `claude-haiku-4-5-20251001` as Critical Reviewer/Verifier.
- One round, Checkpoints mode, Observer off.
- Six normal provider calls maximum; no unchanged retry.
- The room had to stop at the pending Human Gate. Codex did not approve, reject, or request another round.

## Source Pack

- Objective: improve the supplied resume for truthful Google Early Career recruiter screening, prioritizing material fit, evidence quality, scanability, and claims requiring user verification.
- Artifact v1: 3,953 characters.
- Archived job-description summary: 1,038 characters.
- Truth constraints: 623 characters, including no invented metrics, dates, responsibilities, eligibility, accessibility work, AI-tool usage, or AI-tool impact; unresolved placeholders must be removed or explicitly left for verification; absolute claims require evidence.

## Run

- Both independent proposals and both cross-reviews completed without provider or format failure.
- The reviewers produced six Findings.
- The Human Chair accepted two source-bounded Findings: remove the unresolved AI-tool placeholder, and bound unsupported absolute wording in the project bullets.
- The Human Chair rejected four Findings: two positive observations that required no edit, an unsupported campus-location concern, and an unsupported project-naming concern.
- Editor and Verifier completed directly. No retry or resume was used.
- The room reached the pending Human Gate with three declared Changes and a passing verification report.

## Artifact Result

The deterministic Change Set:

1. Removed the unresolved `[FILL IN OR DELETE]` AI-tool bullet.
2. Changed SledTrace wording from `reduce false positives` to `mitigate false positives`.
3. Changed Iridium wording from `eliminate redundant computation` to `reduce redundant computation`.

Artifact v2 remained detailed and preserved all undeclared text. Rejected Findings did not leak into the result.

## Quality Assessment

The transport, checkpoint, Editor, deterministic application, Verifier, restoration, and Human Gate path passed. The user-value Gate did not fully pass.

Useful outcomes:

- The unresolved placeholder was removed rather than fabricated.
- The genuinely absolute `eliminate` claim was weakened.
- The detailed resume remained available separately from the short Brief.
- All declared Changes were visible and traceable.

Material failures:

- Both reviewers missed the truth constraint's explicit concern about the Nature Conservancy `~50%` improvement claim, so the Chair had no Finding to accept for that issue.
- The Critical Reviewer incorrectly treated `reduce false positives` as an absolute claim. The Editor changed it to the vaguer `mitigate`, which does not materially improve evidentiary truthfulness.
- The Verifier repeated that faulty premise and marked the Change supported. It verified lineage to an accepted Finding, but did not independently verify the semantic quality of the Finding or rewrite.
- The Brief reported no remaining human checks even though the unresolved `~50%` metric remained in Artifact v2.

## Usage

- Provider calls: 6.
- Displayed input: `14K` tokens, rounded by the UI.
- Output: 3,057 tokens.
- Model time: 48 seconds.
- Application estimate: `$0.046`.
- Provider invoices remain authoritative.

## Gate Result

**Partial failure.** The complete bounded workflow is now proven against a realistic artifact, but the result is not yet reliable enough for a user who delegates the review and reads only the final deliverable. M2.11 remains current.

## Next Correction

Implement the smallest evidence-driven correction before another paid full benchmark:

1. At the cross-review checkpoint, let the Human Chair add or revise a bounded, source-linked Finding before Editor work.
2. Make the Verifier independently test whether each rewrite improves truthfulness and satisfies the source constraint; Chair acceptance proves authorization and lineage, not semantic correctness.
3. Add deterministic regressions for a missed explicit metric constraint and for the false claim that `reduce` is absolute.

Do not add generic orchestration, more agents, or cost micro-optimization first.

# Detailed Plan Smoke 007

Date: 2026-08-27
Status: Working protocol passed; Plan artifact failed

## Objective

Produce a directly executable 12-day LeetCode plan for a candidate with Easy and partial Medium ability. Each day was constrained to 2-3 hours and at least 10 Medium Equivalent Units (MEU), where `1 Medium = 1 MEU`, `1 Hard = 2 MEU`, and `3 Easy = 1 MEU`. Approximately 3-4 MEU had to be new work, with the rest from timed redo, error recovery, or verbal review.

Every day had to include concrete LeetCode IDs and English titles, difficulty, new/redo/verbal labels, an MEU equation and subtotal, minute-level time boxes, completion criteria, error carry-forward, stage checks, fallback rules, and rest.

## Configuration

- OpenAI `gpt-4.1-mini`: Strategist and Synthesizer
- Anthropic `claude-haiku-4-5-20251001`: Technical Lead
- One round, Checkpoints, Observer off
- Decide synthesis cap: 4,800 output tokens

## Evidence

- Both proposals completed and accepted the MEU split as feasible only when redo work is time-bounded.
- OpenAI cross-review completed. The first Anthropic review returned invalid JSON.
- The Human Chair appended a format and language correction. One explicit changed-input recovery succeeded and recommended a Day 1 diagnostic with a 2-5 new-MEU adaptive range.
- Final OpenAI synthesis used 2,092 output tokens, 26 seconds, and a `$0.017` application estimate, then failed the application contract with `The plan Deliverable is missing Day 2.`
- The contract correctly withheld the incomplete artifact from Human Gate. The room exhausted its six-call allowance because the Anthropic review recovery consumed the reserved recovery turn. No unchanged retry followed.

## Gate Result

The MEU objective, mixed-provider discussion, changed-input review recovery, and strict artifact rejection passed. The detailed Plan artifact failed.

Increasing the memo token cap was not sufficient: the Synthesizer stopped well below 4,800 tokens. A single free-form Decision memo is therefore not a reliable carrier for a 12-unit task artifact with per-unit validation.

## Next Design Boundary

M2.13 should introduce a structured `PlanArtifact` with exactly 12 validated day records. Each record owns topic, recognition signals, concrete task rows, MEU arithmetic, time boxes, completion criteria, and carry-forward rules. Application code should validate and render the records, while a short Decision memo remains a separate executive artifact. Paid recovery should target only missing or invalid day records, not replay proposals, reviews, or valid days.

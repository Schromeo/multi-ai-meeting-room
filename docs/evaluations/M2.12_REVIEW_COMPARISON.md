### Manual prompts

The initial M3 draft is exactly the saved S1 output. For its reviewer, send the same exported public task plus that draft in a fresh context, with:

> Review this draft against the supplied original artifact, references, and truth constraints. Identify material corrections, missed constraints, and unsupported or unnecessary edits. Cite supplied text or label inference. Do not assume the author or a prior reviewer is correct. Return concise actionable feedback and remaining uncertainty, not a full rewrite.

For the final M3 author, send the same public task, saved S1 draft, and complete critique, with:

> Independently assess this critique against the supplied evidence. Adopt supported corrections; reject unsupported premises with a short reason. Return the complete revised artifact, a material-change list with evidence or explicit inference, and remaining human checks. Do not treat agreement as verification.

No iterative argument, tool calls, retrieval, repair loops, or answer-key hints. Record the exact prompts and all outputs, including rejected candidates. Count M3's standalone cost including S1 even if the experiment reuses S1 for free; record incremental spend separately.

## Fairness and Human Intervention

- Freeze language, objective, artifact, sources, constraints, and date context across matched runs. Do not give one arm more factual background or the oracle.
- Require the same detailed user deliverable. S1/M3 may use plain text; R6 retains its production Change Set. Do not force baseline models to spend tokens on app transport JSON.
- Record exact provider/model ID, reasoning parameters (including omitted/default), output caps, prompt hashes, application revision, and failures. Cap values must permit a complete artifact; do not tune them after viewing a score.
- Record actual budgets and limits per arm. One call versus six calls is a workflow comparison, not a controlled claim about model diversity alone. If R6 appears better, an optional same-model three-pass control is needed before attributing the difference specifically to a second model rather than more inference effort.
- At R6's checkpoints, the operator may accept/reject only published Findings using public evidence. Log each action; do not silently inject oracle issues. If intervention is needed, preserve the unassisted result and mark the run assisted.
- Score the model artifact before human editing. Then offer every arm the same predeclared human-edit time budget and save the adopted version separately. Human-supplied issues or fixes never count as model discoveries.
- Hide arm/model labels from the scorer where practical. Otherwise report unblinded scoring. The operator who authored these fixtures is not an independent evaluator.
- A malformed/failed response counts as a failure with its spend, not an excluded sample. Recovery requires a new brief and is reported separately; no success-only averaging.

## Rubric

Use the same scorer and rubric for matched artifacts. Inspect the detailed artifact before its explanation or claimed verification. For each oracle issue, record `found / missed / unknown` and `repaired / partial / unchanged / unknown`, citing output spans. Warnings in a brief can count as detection but cannot count as repair if the defective assertion remains in the artifact.

| Dimension | Measurement and interpretation |
| --- | --- |
| Mechanical | Completed artifact or exact failed phase; separate from quality |
| Detection | Weighted supported issue recall: blocking=3, material=2, minor=1; deduplicate by underlying issue; unknowns remain unscored |
| Repair | Weighted fully repaired issues / total known issue weight; partials are reported separately, not full credit |
| False positives | Count distinct unsupported material Findings and harmful adopted edits; cosmetic rewrites receive zero material-improvement credit |
| Artifact usability | 0=missing/unsafe; 1=complete but needs material repair; 2=adoptable for the stated purpose with honest remaining checks |
| Preservation | Supported claims, scope, and useful details retained by meaning; exact wording is not required |
| Human effort | Pre/post-edit artifacts; intervention count; measured reading/edit time and changed passages; unknown if not observed |
| Economics/experience | All calls including failures, input/output and reasoning usage when reported, elapsed time, application estimate versus invoice, characters shown/read as a disclosed proxy only |
| Differentiation | Source-supported, material, human-accepted improvements absent from comparable S1; causal category below |

No single aggregate score can cancel a blocking truth/consent/data-loss violation. A blocking issue left in the artifact, a newly invented material claim, or removal of required scope blocks adoption. A disclosed open verification task is acceptable only if the artifact no longer states its unresolved claim as fact or completed work.

Report issue counts and weights alongside rates. If any issue outcome is unknown, withhold the overall recall/repair percentage and report assessment coverage instead; never silently drop unknowns from the denominator.

The seeded issues are not exhaustive. A sound new issue is recorded with evidence and scored retrospectively across all available arms under a versioned rubric change, never only credited to the favored arm. Do not turn a Verifier's `supported` status into a human truth score.

### Attribution

For every claimed unique improvement save: source excerpt -> original model position -> independent Finding/objection -> changed position -> final before/after -> human acceptance.

Classify it as independent-proposal diversity, cross-review-induced correction, Editor-only improvement, human-supplied correction, or unknown. Only the second category, with an observable change after the objection, supports a cross-review claim. Repetition, rewording, a different provider logo, and an issue already fixed by S1 do not. Missing artifacts or unmatched inputs mean uniqueness is unknown, not positive.

# M2.11 Correction Brief：逐项 Change 编辑

日期：2026-08-27
状态：已完成

## 已观察失败

Artifact v2 Benchmark 005 使用确定性 Change Set 到达 Human Gate，但 Chair 只能整体批准或拒绝。某条语义薄弱的改写无法直接修正，只能花钱启动更广泛的模型回合。

## 用户 Artifact

一份可由 Chair 编辑的 Review 结果：每条 Change 的原文、Finding 来源链、位置、理由和模型 verification 保持不可变；Chair 可以修改 replacement 文本，并得到由应用派生的 Artifact v3。界面必须明确模型 verification 只覆盖 v2，不覆盖人工改写。

## Baseline

当前 v0.11h 只读展示 Artifact v2、Change Set、Verification 和 Brief。用户只能整体批准、拒绝或添加方向再开一轮。

## 最小假设

在现有 Human Gate 增加有限的逐项 replacement 编辑，无需新增供应商调用或扩大协议，就能提高产物可采用性。

## 预期信息增量

不增加模型调用。本切片只验证现有带来源 Change Set 是否足以支持人工修正和持久恢复。

## 验收检查

- 只有 Change 的 `after` 文本可编辑；来源与 lineage 字段不可修改。
- 确定性拒绝未知 Change ID、未改变草稿、超长 replacement、来源不匹配、歧义和重叠。
- Artifact v3 始终由应用代码根据不可变 Artifact v1 与编辑后 Change Set 派生。
- 人工编辑与模型已验证的 v2 内容有明确视觉区别。
- Revision 保存到 Meeting History，并能在不恢复凭证的情况下重新打开。
- 旧 v2 记录继续可读。
- 自动测试、production build、ESLint 与 `git diff --check` 通过。

## 成本边界

零供应商调用、零付费 token。只允许本地确定性测试和浏览器 QA。

## 停止条件

如果逐项编辑需要修改供应商 prompt、重跑 Review、引入新的通用工作流引擎或弱化来源链校验，则停止并拆分。本切片之后再处理不可变最终批准，除非它可以直接复用 revision record 且不扩大范围。

## 结果

本地证据支持该假设。Chair 可以编辑单条 replacement、恢复模型原文，并得到由应用派生的 Artifact v3；原 Change 身份和 Finding 来源链保持不可变。Artifact v3 与 revision record 分开持久化；界面明确说明模型 verification 只覆盖 v2。没有修改供应商 prompt、增加模型调用或新增通用协议 phase。

Production build、ESLint、`git diff --check` 和全部二十九项自动测试通过。1280x800 与 390x844 浏览器检查没有页面溢出或控制台警告。刷新后的本地浏览器没有保存的 Review result，因此交互式 v3 Decision 页面检查留给下一次自然生成或恢复的 fixture；本轮没有为了截图单独运行付费房间。

# Plan 质量闭环

- 已知失败：core-closure-check 中对第 2 天的具体意见没有改变交付计划。通用短职责和最低推理不是质量策略。
- 用户交付：完整逐日计划、不可变原版、选定意见、修改或拒绝的依据、独立改动复核、精确的人类批准快照。
- 基线：已保存的离线负面特征测试；历史 Plan 007 交付失败。本轮不声称完成单模型匹配对照或证明比较优势。
- 假设：有界、任务化的修改和复核能把关键意见转成可检查的改进，不重写无关天数。
- 范围：每份原计划最多选三条意见，一次修改和一次不同席位复核。调用意图和草稿先持久化再继续；不自动重试。失败或中断可以放弃修改、保留原版；人工编辑需先结束或放弃本轮。
- 质量配置：保留用户所选模型，为 Plan 交付阶段留出输出空间，对已识别 GPT-5 系列使用 medium 推理。其他模型和厂商保留默认值，不冒充已启用深度思考。不建模型市场或新推理控制台。
- 验收：只改对应天数；完整计划约束有效；选定意见逐项回应和复核；允许拒绝错误批评；保留未解决和未选择的问题；来源绑定、持久化和批准正确；失败后没有额外调用；披露成本和未知用量。
- 成本：开发零真实调用。之后用户触发修改最多两次调用，输出上限分别 12,000 和 6,000 token，不是账单封顶。真实测试另行授权，不沿用旧 $0.10。
- 停止：离线闭环成立且本地构建通过。教学质量和多模型优势仍待验证；下一步仅一次有信息增益的授权真实案例，不扩展 UI 或评测平台。

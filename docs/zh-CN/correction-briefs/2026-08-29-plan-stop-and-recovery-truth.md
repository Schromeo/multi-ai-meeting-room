# Plan 停止与恢复真实性纠错简报

- **已观察失败：** Plan 房间额度耗尽后仍可能显示 `Build missing plan days` 或 `Resume saved plan`，即使续接后的状态仍超过输入/输出 token 上限。重开后所有 `stopped` 协议都显示为 `Stopped by the Human Chair`，包括确定性的预算停止。
- **用户产物：** 保留所有已接受 Plan 日期与尝试回执。本轮只改变下一动作是否真实可用，以及房间为何停止的说明。
- **最小假设：** 协议状态丢失停止来源；界面只按结构资格推导恢复，不会用保存用量评估拟议恢复状态。
- **改动边界：** 增加向后兼容的可选协议 `stopReason`，值为 `human` 或 `budget`；预算 Gate 持久化 `budget`，显式取消持久化 `human`，旧 stopped 房间显示未知而不是误写为人类停止。启用或标记任一恢复控件前，用保存用量评估准确的拟议 Plan 恢复状态。
- **验收：** 无 `stopReason` 的旧协议仍可解析；非法值或非 stopped 状态携带 reason 会失败；预算停止与人工停止分别往返；恢复状态清除旧停止原因；输入/输出已耗尽时恢复明确不可用且不能进入 handler；仍有预算的结构合法恢复继续可用。
- **费用与停止边界：** 零供应商调用，不提高预算、不扩大恢复政策、不重写旧记录、不重做界面。离线构建/测试/lint/类型检查及双语文档完成即停止。

# 修正简报——普通会议可配置 Setup

状态：已实施并通过本地验收；真实模型校准及已保存会议浏览器回放仍待验证。仅普通 Decide，不调用付费模型。

1. **观察到的问题：** 用户不能配置超过三个席位，不能为特定任务命名席位职责，也不能调整 Lite/Medium/长篇档的单次输出上限。Setup 位于连接弹窗；已有真实中文会议表明 600 token 上限与可见篇幅相差很大。保存的创作会议 Live 001 是用户案例和基线。
2. **用户产物：** 页面内 Setup 区域和可复用连接；2–12 个明确配置的普通会议席位，每席包含供应商/模型、角色、可选显示名称和有界 Skill/职责；Lite、Medium、Extended 分别可调整席位单次调用与最终 Memo 的传输上限。启动前显示调用次数及派生的会议额度；保存的会议保留席位身份和预算选择。
3. **现有基线：** 固定三个席位行，只允许 2–3 席；连接库是弹窗；席位上限为 600/1,200/12,000 token，总结上限为 2,400/4,800/16,000 token；提示词字数和 4,000 字符发言校验另行限制。Review、Plan 有独立产物合同。
4. **最小假设：** 将有界配置贯通界面、路由、提示词和派生预算，就能解决不一致，而不增加模型调用、Task Pack、重试或通用 Agent 框架。
5. **预期信息增益：** 离线样例验证席位数、身份、提示词、单次上限和房间总额一致。本切片不授权付费调用；默认值是否适合真实模型，须由用户后续会议验证。
6. **验收：** 默认和自定义设置在客户端/服务端均校验；普通 Decide 的 12 席不被暗中钳回三席，第 13 席被拒绝；旧房间可读；自定义文本有界且不取得协议权威；活动房间保持原设置；无效组合不会启动付费工作；`pnpm.cmd check` 通过；若本地 UI 可运行，检查一次小窗口布局。
7. **成本边界：** 零模型调用、零外部发布。预检随席位数增加，并说明 token 上限不是可见篇幅保底或账单上限。保留 Review、Plan、Observer 和 Solo 现有路径。
8. **停止条件：** 若十二席需要改写 Review/Plan 语义、自主路由或无界 Canonical State，应隔离这些路径，不扩大本切片；有残余不兼容时停止并如实报告，不宣称完整验收。

本地证据：`pnpm.cmd check` 通过构建、85/85 项离线测试、lint 和类型检查。模拟 12 席流程到达 Memo，第 13 席被拒绝。在 390×700 下，Setup 可滚动到输出设置和 Done，Setup／Agenda 切换能更新选中态。未使用付费模型或已保存会议回放。

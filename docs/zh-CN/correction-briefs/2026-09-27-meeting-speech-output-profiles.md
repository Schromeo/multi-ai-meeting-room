# DP-0.3 — 会议发言跟随 Output Budget 深度

- **已观察失败：** 用户在选择 Lite、Medium 或 Uncapped 后，仍看到较短的 Seat 发言。普通 Discuss 的供应商输出 token 上限虽按档位变化，提案、审阅、定向辩论 prompt 却始终要求相同的 140／120／80 词，并要求提案简短。
- **用户产物：** 可见的参与者发言随所选档位呈现有意区分的深度，同时保留独立提案、有依据的审阅、带来源的卡片、有界回合和可阅读的最终输出。
- **基线：** 页面直接显示通过校验的 `statement`，没有事后摘要步骤。Medium／默认提示为 140／120／80 词；`lite` 与 `unlimited` 虽有不同传输上限，却共用同一发言指令。最终总结已有独立的输出档位路径。既有 statement 4,000 字符上限及 Card／Canonical State 限制保留。
- **最小假设：** 将已解析的 Output Profile 传给现有提案、审阅和定向辩论 prompt 构造器，使 statement 指引按档位变化。Lite 简短，Medium 保留现有平衡，Uncapped 允许更充分但聚焦的发言。Turn Envelope、解析器、供应商上限、调用次数、重试规则及 Review 来源约束不变。
- **预期信息增益：** 离线模拟供应商请求可证明三个档位在一次性和可恢复阶段收到不同发言指令，零付费调用。这验证指令传递，而非模型遵从或质量。
- **验收：** 三档提案、交叉审阅与定向辩论的目标深度不同；Medium 保留旧上限；Review 仍要求有来源的 Finding；所有档位保留既有结构合同、语言规则和供应商上限。`pnpm.cmd check` 通过；无 UI 遮挡或已存房间 schema 变化。
- **成本边界：** 零真实供应商调用，不增加回合、重试、依赖、迁移或部署。真实使用 Uncapped 可能增加输入／输出、阅读量；现有供应商和房间预算仍为准。只测试离线 fixture。
- **停止条件：** 若某档位无法适配现有 statement／Card 校验，不在本次放宽解析器或增加修复调用；记录冲突并保持有界。真实发言长度与价值需要以后经授权的实际证据。

## 本地结果

- Lite／Medium／Uncapped 分别将提案 statement 指向 70／140／350 词，审阅为 60／120／280 词，具名分歧发言为 50／80／160 词。这是 prompt 上限与深度指令，不是词数硬校验，也不保证模型填满额度。既有严格 JSON、工作发言 4,000 字符、Claim／Card 限制及来源政策仍生效。
- 档位已传入一次性与可恢复的提案／审阅及定向辩论调用。最终 Memo 和结构化 Plan 继续使用各自合同。既有传输和房间预算继续控制成本；没有增加调用或重试。
- `pnpm.cmd check` 通过：构建、78/78 离线测试、lint 与生成类型检查。模拟请求验证三档、两条会议执行路径、定向辩论、语言指令、上限和调用次数。本次没有真实供应商、浏览器、远程 CI、推送或部署验收。
- 恢复的旧房间没有历史 Output Profile 记录；当前 UI 默认仍为 Medium。本次不推断过去的选择，也不改已存房间 schema。真实模型的详细度、输出质量和阅读负担尚未测量；本地指令路由到此停止。

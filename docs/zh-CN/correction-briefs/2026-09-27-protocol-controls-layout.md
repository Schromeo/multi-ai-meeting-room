# DP-0.3 — 会议控制区布局纠错

- **已观察失败：** 用户截图显示 Chair Control、Round Allowance、Output Budget 在狭窄 Seat 编排栏中重叠。编排栏是桌面网格的一列，但 `.protocol-setup` 始终等分三列；每个分段控制所需宽度超过所分得的列宽。只按视口宽度触发的单列规则在桌面窄侧栏中不会生效。
- **用户产物：** 三组控制在同一会议设置区清晰可读、互不重叠，标签和行为保持不变。
- **基线：** 约 370px 的编排栏三等分后，每组只有约 110px，而 Chair Control 有三个按钮。用户截图是视觉 fixture。
- **最小假设：** 让控制组按自身可用宽度换行，不改变任何状态或策略行为。
- **预期信息增益：** 窄宽度视觉复查可以判断碰撞是否仅由布局尺寸导致；无需供应商调用。
- **验收：** 标签、按钮、下拉框和说明文字均留在各自组内；截图对应窄宽度下无横向溢出或重叠；更宽布局仍可用；既有构建、lint、测试和类型检查通过。
- **成本边界：** 仅改 CSS，不调用模型、不改依赖、不部署。
- **停止条件：** 若换行仍不能消除碰撞，先测量宽度再调整组件结构；不重设计周围 Seat 编排栏。

## 结果

- `.protocol-setup` 现按自身可用宽度换列；组件逻辑、标签和会议策略均未改变。
- 本地浏览器在 1280px 视口下，369px 编排栏内三组各占完整一行；实测控件都在各自组内，目视无碰撞。390px 视口下仍各自分行，页面无横向溢出。
- `pnpm.cmd check` 退出 0：构建、75/75 测试、lint 和类型检查通过。Wrangler 在生成类型时有不阻塞的沙箱日志写入警告。未调用供应商、未部署。

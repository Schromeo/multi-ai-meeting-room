# 纠错简报——Setup 职责与有界 Agenda 席位摘要

状态：已实施并通过本地验收；使用真实凭据的就绪态浏览器检查仍待完成。零供应商调用。

1. **观察到的问题：** 十二个席位使 Agenda 的 Room Composition 变成很长的重复表单；Skill 在这里和 Setup 重复。直接从 Setup 点击 Agenda 可能未关闭 Setup，导致「①」仍被选中。
2. **用户产物：** Agenda 中固定高度、内部可滚动、只读的席位摘要；增加、删除、模型、角色、名称和 Skill 的编辑集中在 Setup。可运行的 Setup 完成并切到 Agenda 后，「①」显示绿色完成态。
3. **基线：** Agenda 逐席显示选择器和 Skill 文本框；`.workspace-frame:has(.entry-switcher) .seat-list` 强制列表无限展开。`connectionOpen` 仍为真时，阶段导航始终将 Setup 视为当前步骤。
4. **最小假设：** 只将 Agenda 的席位表单换成紧凑摘要、限制列表高度，并在选择其他阶段时关闭 Setup；保持共享席位草稿、校验、供应商路径和已保存房间结构不变。
5. **预期信息增益：** 离线组件／源码检查与本地窄窗口走查验证十二席是否都可查看，同时 Agenda 页面不再被拉长。
6. **验收：** 十二席摘要在固定高度区域内滚动；Agenda 不能改 Skill，Setup 仍可编辑；直接 Setup→Agenda 后 Agenda 选中，且至少两席可运行时 Setup 显示绿色完成态；窄窗口无横向溢出；`pnpm.cmd check` 通过。
7. **成本边界：** 不调用模型、不加依赖、不改持久化、不对外发布。
8. **停止条件：** 如果需要改动角色语义或会议执行，就停在展示边界并报告问题。

本地证据：`pnpm.cmd check` 通过构建、86/86 项测试、lint 和类型检查。Setup 的十二席在 Agenda 中显示为十二条只读摘要；390×700 下列表内部滚动且 Start 仍可到达。有效就绪时的绿色状态通过源码／CSS 测试检查，没有使用凭据。

## 用户补充：席位参与开关的例外

- **观察到的问题／用户产物：** 用户截图中 Agenda 摘要有 Off 席位，却不能在这里重新打开；Setup 也只有 Add／Remove，没有 On／Off。
- **基线／最小假设：** 现有 `SeatDraft.enabled` 已控制可运行席位和预算；在两个界面展示同一开关，不允许 Agenda 编辑其他席位字段，也不改变执行语义。
- **信息增益／验收：** 离线检查与无密钥浏览器走查确认两处都能操作、共享同一状态、运行时禁用，Off 席位保留配置但不计入可运行数量。
- **成本／停止：** 零供应商调用、不改结构；若切换需要第二份状态或隐式重试，则停止。

## 用户补充：参与开关前的配置门槛

- **观察到的问题／用户产物：** 席位缺 API 连接／模型，或 Custom role 缺名称、Skill 时，仍可能显示 On／Off。用户要求显示 “Not set up”，配置完整前不能切换参与状态。
- **基线／最小假设：** 独立于 `enabled` 推导一份配置结论，再同时用于两处开关、Agenda 标签、可运行席位及启动校验；配置未完成时保留草稿。
- **信息增益／验收：** 覆盖缺连接／API key、缺失或不兼容模型、无效角色、Custom 名称／Skill、配置完成后的 Off／On，以及清空字段后的状态回退。启用但配置不完整的席位不得触发供应商调用。
- **成本／停止：** 零供应商调用，不改保存结构或角色协议；若现有连接元数据无法可靠表达配置结论，则停止。

配置门槛的本地证据：`pnpm.cmd check` 通过构建、87/87 项离线测试、lint 和类型检查。无密钥浏览器检查在 Agenda 与 Setup 都看到 `Not set up`，这些席位没有参与开关，Start 处于禁用状态。使用真实凭据验证从完成配置到出现开关的流程仍待完成。没有供应商调用、提交、推送或部署。

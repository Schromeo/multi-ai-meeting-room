# DP-0.3 — 窗口化布局可达性纠错

- **已观察失败：** 本地浏览器窗口为 1280×720 时，Agenda 表单高 1,133px，而工作区仅高 556px。工作区和应用隐藏溢出，折叠线以下的会议控制与 Start meeting 无法通过滚动到达。1024×600 时页眉阶段导航还会挤到 Meetings 等操作。用户反馈必须全屏才能看到全部内容。
- **用户产物：** 普通窗口中无需缩放或最大化，也能到达 Setup/Agenda 的全部控件和操作；实时 Meeting 视图保留现有阶段布局。
- **基线：** 本地 Ask the Room 截图在 Seat 3 处被截断。Start meeting 约从页面 1,218px 处才开始，document/body 可滚动高度仍只有 720px。
- **最小假设：** 为入口／Agenda 工作区提供一个纵向滚动通道，让表单按内容确定高度，同时保留实时 Meeting 的有界布局。让页眉阶段导航在发生拥挤前提前切换为现有的底部导航。Decision 侧栏内容超过窗口时，让该侧栏内部滚动。
- **预期信息增益：** 在窗口化桌面、平板、手机尺寸测量并目视检查，区分裁切与横向溢出；无需供应商调用。
- **验收：** 在 1280×720、1024×600 和更窄的代表性视口下，Agenda 底部操作可滚动到达，页眉／入口／模式控件可用，且无横向溢出或控件重叠。Chat 与 Browse Packs 仍可访问。既有检查通过。
- **成本边界：** 仅改 CSS；不改依赖、状态、供应商、付费调用或部署。
- **停止条件：** 若仍不可达，先测量失效的滚动容器再改页面结构；不重设计 Meeting 协议或 Task Pack。

## 结果

- 入口／Agenda／Chat／Packs 现共用工作区纵向滚动；Agenda 和 Solo 内容按自身高度展开，Seat 列表不再制造竞争性的内部滚动区。实时 Meeting 布局未改。过高的 Decision 侧栏现在有自己的纵向滚动边界。
- 阶段导航从 980px 提前到 1180px 切换为现有底部位置。1181px 时实测页眉各组未重叠；1024×600 时阶段导航与页眉操作分离。
- 本地浏览器在 1280×720、1024×600、900×650 和 390×700 下检查：Agenda 底部操作可滚动到达，页面无横向溢出。390×700 下 Chat 的 Send 操作通过同一个工作区滚动可达；Browse Packs 可见。1024×600 的 Connection 弹窗保持在视口内，内容可内部滚动。
- `pnpm.cmd check` 退出 0：构建、75/75 测试、lint 和类型检查通过。Wrangler 生成类型时出现不阻塞的沙箱日志写入警告。未调用供应商、修改已存房间、运行远程 CI 或部署。
- **限制：** 本地浏览器没有配置 Connection 或已保存房间，因此实时 Meeting 与恢复的 Decision 页面未作浏览器实测。Decision 侧栏滚动只是 CSS 边界检查，不代表端到端验收完成。

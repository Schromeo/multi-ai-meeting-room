## OpenAI 独立基线

OpenAI 第一份提案生成时尚未看到另一个模型的内容，因此作为本次评测的房间内单模型基线保存。它建议：

- 通用同步会议室，包含 3–5 个 AI 和 1 名人类 Chair；
- 角色分配、轮流发言、共享 agenda/state、主持控制和可搜索 transcript；
- 默认不允许外部联网、后台自治、文件执行或持久代理记忆；
- 由人决定联网级别、最大席位数和持久化范围。

它不是单独计时的一次 standalone API 调用，因此可以比较内容增量，但还不能完整比较单模型费用与延迟。

## 多模型新增价值

Anthropic 提案与两次定向审阅增加了 OpenAI 独立提案中没有的关键内容：

- 第一版应针对重复出现的决策类别，而不是通用会议室；
- 角色差异应对应不同错误代价，例如 precision、recall 与 assumption audit；
- 把 Chair 能力和认知负担列为显式系统约束；
- 用 3–5 个真实案例做带通过标准的 pilot；
- 分开经验性主张、假设和价值判断；
- 保留席位数、联网、范围和 Chair 能力方面的分歧。

最终 memo 吸收了这些新增内容，并保留未解决分歧，没有伪造共识。这是结构化跨模型审阅产生真实增益的正面信号。

## 暴露出的风险

- **阅读负担：** 只有 62 个字符的目标产生了 3,424 output tokens，日常使用过长，需要 Turn Envelope、卡片上限、Round Brief 和定向上下文。
- **认识论泄漏：** 4 小时会议、30 秒 override、3 年 Chair 经验或 5 次既往决定都只是设计假设，不是证据，但部分数字仍进入了最终 memo。
- **系统角色偏差：** 综合默认复用了 OpenAI Strategist，而不是用户显式选择、单独记账的 Final Synthesizer。
- **兼容性：** 模型发现只能证明 Key 有权看到模型，不能证明所有可选生成参数都受支持。
- **人类控制：** v0.6 只有最终 Gate，没有安全的会议中 checkpoint 或有范围的 Chair Directive。

## Gate 结果

**可以进入下一架构里程碑，但先修复兼容性。**

真实路径证明两个供应商可以完成提案、指定审阅、综合、用量报告、保存和有限 Human Gate，但还不能证明广泛产品价值。输出过长、任意细节进入结论、系统角色不明确以及仅在最后允许人介入，都直接支持已经批准的 Protocol v1。

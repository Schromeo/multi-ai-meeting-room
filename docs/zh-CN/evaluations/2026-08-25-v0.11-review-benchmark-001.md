## 评测范围

- Artifact v1：用户提供的简历正文；发送给供应商前移除姓名、电话、邮箱、LinkedIn 和 GitHub 身份信息。
- 参考资料：此前用户讨论中保存的 Google JD 摘要。评测时原职位链接已经不可用，因此明确禁止根据摘要推断当前职位状态或申请资格。
- 真实性边界：不得虚构指标、日期、职责、资格、引用、无障碍工作或 AI 工具影响；括号占位符保持未解决。
- OpenAI `gpt-4.1-mini` 担任 Strategist，Anthropic `claude-haiku-4-5-20251001` 担任 Critical Reviewer。
- Checkpoints、单轮、Observer 关闭；每次运行包含两条独立 Finding、两条交叉 Review 和一次 synthesis。
- 沿用有限烟雾评测中用户批准的 `$0.10` 应用提示性估算上限。

## 有用 Finding

两次运行都发现了若干可执行证据问题：

- 提交前删除未完成的 `[FILL IN]`、`[X]` 和指标占位符；
- 如果没有真实 before/after 数据，HBase cache tuning 保持定性表述；
- 为 Nature Conservancy 约 50% 的提升补充 baseline 或验证背景，无法验证时降低主张强度；
- 真实说明 AI 工具用途，不为了贴合 JD 编造影响 KPI；
- 保留简历中分布式系统、信息检索、全栈和开源项目的强证据。

这些内容与此前手动 GPT-to-Claude 审阅部分重合，但本次在一条有限、共享来源的工作流中重新得到。

## Run A 失败

程序没有提供可信当前日期。两家供应商都错误地把 2024 或 2025 的经历当成未来日期。Human Chair 写入 `2026-08-25` correction，随后 veto 错误时间线 Finding，但后续模型仍提升了同一 Claim。最终 Review Brief 一边否定部分时间线问题，一边又建议修改同一条已经过去的工作日期，内部自相矛盾。

Memo 被拒绝。这证明自由文本 Chair Directive 只是 prompt 建议，不是有约束力的逐项决定。

## 第一次修复后的 Run B 证据

服务端注入可信当前日期后，原“未来日期”错误消失。Anthropic 随后产生另一条薄弱推断：把 2019 暑期实习早于 2022 毕业当成可信度问题。在 Proposal checkpoint，Chair 通过新的逐项控件 Accept Finding 1、2、5，并 Reject Finding 6。

交叉 Review 仍口头重复被拒绝的时间线问题，但 Canonical State 保持 `rejected_by_chair`；后续 support 和 objection 无法覆盖 Human Choice。Review synthesis 不再读取原 reviewer statement，只读 Canonical State，并正确写明实习时间线按原样接受。

结果仍未通过产品 Artifact 契约：它省略全部五个必需 Review Brief 标题，并增加当前 Artifact 没有提供的 GitHub link 建议。Memo 被拒绝。应用代码现会校验所有必需标题恰好出现一次且顺序正确；失败会显式显示，并且绝不自动重试。

## Gate 结果

**部分通过；继续 M2.11，但不再付费重试。**

Review Agenda、共同来源包、独立 Finding、checkpoint 逐项决定、本地审计和有约束力的 Human Chair 权限已经获得真实证据。详细 Review Brief 契约尚未真实通过，Artifact v2 也不存在。最终代码修复已有确定性覆盖，但由于合计估算已达到 `$0.10` 上限中的 `$0.087`，不再付费复测。

## 由证据形成的产品决定

1. Review 由系统注入可信时间上下文，不能要求模型猜当前日期。
2. 自由文本 correction/veto 仍可作为上下文，但 Claim 接受或拒绝必须是类型化、确定性的 Human Choice。
3. Chair 决定后，后续模型更新只能添加审计证据，不能修改 Claim 状态。
4. Review synthesis 只读 Canonical State；被拒绝 Claim 是强制排除项，已解决 Dispute 不再开放。
5. 必需 Artifact 结构由应用代码验证，不能只写在 prompt 中。

# M2.12 Review 对照包

日期：2026-08-27

## 问题与边界

结构化多模型 Review 能否在可接受的费用和人工负担下，交付比强单模型或人工转贴审阅更好、可采用的产物？

本包冻结输入和判分，不预设答案。Stage Replay 008 是格式正例，不是 Verifier 能拒绝错误前提的证据。Benchmark 005 是历史诊断，不是下面小型合成案例的配对基线。不使用真实个人资料、实时 Google 招聘资格或其他外部时效事实。

## 固定案例

模型公开输入：[cases.json](../../../tests/fixtures/review-evaluation/cases.json)。仅供判分者使用：[oracle.json](../../../tests/fixtures/review-evaluation/oracle.json)。

| 案例 | 用户产物 | 检查的已知问题 |
| --- | --- | --- |
| `resume-truth-v1` | 完整修订简历 | 无依据指标、占位符、绝对声明；保留已有依据的有限表述 |
| `requirements-control-v1` | 可实现的产品需求 | 删除不符合同、发送缺少批准、验收不可测试 |
| `technical-recovery-v1` | 修订后的实现方案 | 确认时序、模糊外部结果引发重复副作用、无依据性能保证 |

每例有三个预置问题、准确证据锚点、应保留的含义、误报陷阱、待确认事项和一份参考产物。Oracle 是评测辅助，不是穷尽的真理或必须逐字匹配的答案；同样合理的修订也有效。生产解析器测试只能证明参考修改机械可应用，不能自动判定语义正确。

不得把 oracle 发给任何模型，包括 Editor 和 Verifier；评分运行中的 Chair 干预也不得偷看答案补漏。公开提示只导出目标、原始产物、参考材料和约束。案例修改必须升级版本，旧新结果不能混算；每次记录准确导出输入及其 SHA-256。

## 本地命令

在项目目录使用项目支持的 Node 运行时：

```sh
npm run review:case -- list
npm run review:case -- task resume-truth-v1
npm run review:case -- prompt resume-truth-v1
npm run test:review-eval
```

命令仅读取本地文件并打印到终端。不使用 API Key、不调用供应商、不启动会议、不向历史导入基线，也不判断模型答案。`task` 输出对应 Review 议题字段，不是完整 API 请求。

### 应用固定入口

本地 Setup -> Connections -> Development / Stage replay -> Probe -> S1 resume baseline 共用同一个公开提示构造器。只有操作者明确点击 Run S1 baseline 才进行一次付费调用，固定 2,400 输出 token、无重试。S1 只支持 `resume-truth-v1`，不接受任意 prompt/case ID/上限。选择器仅在开发 UI 可见，不代表现有 Replay 接口具有单独的生产访问控制。

先约定新预算，再选择 Connection 和准确 Model。Token 上限不是强制美元上限。入口复用现有适配器 reasoning 行为并记录实际请求设置（含省略/默认），不会自动替用户选强模型。当前适配器不保留供应商结束状态，因此收到回复必须标为未评分，并检查完整性。

Download evidence 下载不含凭证的 JSON 回执：准确公开输入、system/user 提示、SHA-256 哈希、模型/配置、原始候选和已知用量。流失败保留部分文本，用量标未知而非零。不写 Meeting；下载前结果只在页面内存中，切换 probe/model 或刷新会清除，请先保存付费回执再开始新 probe。回执不表示语义正确或人类批准。授权调用实际完成前，真实 S1 仍为未运行。

## 对照分组

| 分组 | 流程 | 正常调用上限 |
| --- | --- | ---: |
| S1：强单模型 | 新上下文；相同公开提示；完整产物 + 实质修改 + 待确认事项 | 1 |
| M3：人工转贴 | 复用准确 S1 草稿；另一模型基于相同来源审阅；原模型修订 | 3，含 S1 |
| R6：现有 Review | 相同公开任务；两次独立审阅、两次交叉审阅、Editor、Verifier；一轮、Observer 关闭、Checkpoints、不追加辩论 | 6 |

具体模型 ID 与 reasoning 参数留到付费运行简报确定。不因为某便宜模型已经连接就把它叫作强基线。在现有能力允许时，S1 模型也担任 R6 作者/Editor 与 M3 作者，M3 审阅者担任 R6 另一席位。记录实际角色复用与配置；不为对照新增独立系统角色基础设施。

新授权后先只跑 `resume-truth-v1` 的 S1。保存结果后再判断下一调用能解决什么不确定性，不自动跑三案例或全部分组。有必要才扩展到另外两例。这些已知小型用例用于校准，不是独立保留测试集，也不能据此统计宣称普遍优越。

### 人工转贴提示

M3 起始草稿必须是保存的准确 S1 输出。给审阅者的新上下文发送相同公开任务和该草稿，另加以下英文提示，以便模型实际输入与英文规范一致：

> Review this draft against the supplied original artifact, references, and truth constraints. Identify material corrections, missed constraints, and unsupported or unnecessary edits. Cite supplied text or label inference. Do not assume the author or a prior reviewer is correct. Return concise actionable feedback and remaining uncertainty, not a full rewrite.

给 M3 最终作者发送相同公开任务、S1 草稿和完整批评，另加：

> Independently assess this critique against the supplied evidence. Adopt supported corrections; reject unsupported premises with a short reason. Return the complete revised artifact, a material-change list with evidence or explicit inference, and remaining human checks. Do not treat agreement as verification.

不循环争论、不调用工具、不检索、不自动修复、不提示参考答案。保存准确提示及所有输出，包括失败候选。即使实验复用 S1 不重复付费，M3 独立使用成本也必须包含 S1；增量实际支出另列。

## 公平性与人工干预

- 配对运行固定语言、目标、产物、来源、约束和日期上下文。不能只给某组额外事实或 oracle。
- 要求相同的完整用户产物。S1/M3 可用纯文本，R6 保持生产 Change Set；不强迫基线把 token 花在应用传输 JSON 上。
- 记录准确供应商/模型 ID、reasoning 参数（含省略/默认）、输出上限、提示哈希、应用版本及失败。上限应允许完整产物，不能看分后再调。
- 记录每组实际预算与限制。一调用对六调用是工作流对照，不能单独证明模型多样性价值。若 R6 更好，在归因于“第二个模型”而非“更多推理投入”前，应考虑同模型三次处理的控制组。
- R6 checkpoint 操作者只能根据公开来源接受/拒绝已发布 Finding，并记录动作，不能偷偷注入 oracle 问题。如需要干预，保留未辅助结果并标记 assisted。
- 先评价人工编辑前的模型产物。之后各组获得相同且预先声明的人工编辑时间预算，采用版本单独保存。人工补出的问题和修订不能算模型发现。
- 尽可能向评分者隐藏分组/模型名；做不到则注明非盲评。编写 fixture 的操作者不是独立评审人。
- 格式错误或失败输出也计入结果及成本，不能排除样本。恢复需新简报并单独报告，不只统计成功运行。

## 评分表

配对产物使用相同评分者和 rubric。先看完整产物，再看其解释或自称通过的验证。每个 oracle 问题记录 `found / missed / unknown` 和 `repaired / partial / unchanged / unknown`，引用输出原文。Brief 提醒可算发现，但错误仍留在产物内就不能算修复。

| 维度 | 衡量和解释 |
| --- | --- |
| 机械 | 是否交付完整产物，或准确失败阶段；与质量分开 |
| 发现 | 有来源的问题加权 recall：blocking=3、material=2、minor=1；同问题去重，未知不强行计分 |
| 修复 | 完全修复的问题权重 / 已知问题总权重；部分修复单列，不算满分 |
| 误报 | 无依据实质 Finding 数量、有害采用修改数量；纯换措辞不计实质改善 |
| 产物可用性 | 0=缺失/不安全；1=完整但需实质修复；2=适合当前用途、诚实保留待确认事项 |
| 保留 | 保留有依据的声明、范围和细节的含义，不要求逐字不变 |
| 人工负担 | 编辑前后版本、干预次数、实测阅读/修改时间和改动段落；未观察就是未知 |
| 经济性/体验 | 含失败的全部调用、输入/输出和可得 reasoning 用量、总耗时、应用估算与账单、展示/阅读字符只作为明确标注的代理指标 |
| 差异化 | 相比可比较 S1 独有、有来源、实质且由人接受的改进；按下面因果类别归因 |

总分不能抵消阻断级真实性、批准权或数据丢失问题。产物仍保留阻断问题、捏造新实质事实、删掉必需范围，均阻止采用。待核查事项可以保留，但产物不能仍把该未证实内容当事实或已完成工作。

比率同时报告问题数量和权重。若某项结果未知，不输出整体 recall/修复百分比，改报已完成评判的覆盖量；不能偷偷把未知从分母删除。

预置问题不穷尽全部问题。发现合理新问题，应保留证据、版本化 rubric 变更，并回溯一致地评价全部已有分组，不能只给偏好的分组加分。Verifier 的 `supported` 不等于人工真实性得分。

### 归因

每条独有改善保存：来源原文 -> 原始模型立场 -> 独立 Finding/反对 -> 立场变化 -> 最终修改前后 -> 人工接受。

区分独立提案的多样性、交叉审阅促成的纠错、Editor 自行改善、人工补正和未知。只有第二类且能看到反对之后的变化，才支持交叉审阅价值。复述、改措辞、供应商品牌不同，以及 S1 已修好的问题都不算。缺少产物或输入不一致时，独有性为未知，不是正向证据。
